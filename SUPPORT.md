# Support

Use GitHub Issues after the repository is public for non-sensitive bugs, documentation fixes, and feature requests. Include a minimal safe fixture, Python version, Git availability, receipt schema version, and a redacted command shape.

Do not upload a real Completion Receipt until you have reviewed its sensitivity. For security-sensitive reports, use the private reporting path in [SECURITY.md](SECURITY.md). The project provides local software and does not offer a hosted service or support SLA.
